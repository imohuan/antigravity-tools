## 代理 Key 状态显示 bug 调试（imohuan.shop 部署版）

### 现象
- 用户截图显示 key `ck_3b6ab232`（账号 69045357）标签红色"已耗尽"，但积分 3780
- 调 toggle 后短暂变 active，刷新页面后又显示"已耗尽"
- 用户以为是积分耗尽 bug

### 根因（systematic-debugging 完整 4 步复现确认）
1. **UI 标签 catch-all 误导**：`web/static/index.html:405` 把所有非 active/非 disabled 状态都显示成"已耗尽"红标签。实际 status 是 `abnormal`（被腾讯风控，403 code:11140），不是 `exhausted`
2. **toggle 接口反语义**：`web/api/proxy.py:136` 二元切换把 abnormal 强制改成 active，绕过 `mark_key_abnormal` 注释明确的"不自动恢复"语义。对 exhausted/cooldown/rate_limited/permanent_disabled 同样有此问题
3. **状态机反向覆盖路径**：`_do_proxy_request`（`src/modules/proxy_server.py:3070-3076`）收到 403+code:11140 → 调 `mark_key_abnormal`，把 toggle 改成的 active 又打回 abnormal。5~30 秒内必现

### 完整事件时序（4 步实测）
- t=0s: status=abnormal
- t=1s: toggle 调用 → status=active
- t=5s: status=active（仍稳定）
- t=30s: status=abnormal（被反向打回）

### 仓库内 mark_key_* 调用者穷举
- `mark_key_exhausted`：仅 `_do_proxy_request` 在 429+err_code∈{14018,14019} 时调用（proxy_server.py:3008）
- `mark_key_abnormal`：仅 `_do_proxy_request` 在 403+"code":11140 时调用（proxy_server.py:3076）
- 没有定时任务/同步逻辑会主动改 exhausted 或 abnormal

### Qt UI vs Web UI 状态标签对比
- Qt UI（`src/ui/pages/api_proxy.py:1511`）：active/exhausted/disabled/rate_limited/cooldown/abnormal/permanent_disabled 全部分得很清
- Web UI（`web/static/index.html:405`）：catch-all，只有 活跃/已禁用/已耗尽 三个标签

### 修复建议（未实施，等用户决定）
1. **Web UI 标签细分**：跟 Qt UI 对齐，每个状态独立标签
2. **toggle 接口加状态白名单**：abnormal/exhausted/permanent_disabled/rate_limited 不允许 toggle，需新增 `/proxy/keys/{id}/activate` 接口走 `mark_key_active` 显式恢复
3. 或者 toggle 仍允许切换，但返回 warning 提示"系统禁用状态，恢复后可能立即被再次禁用"

### 工具技巧
- `imohuan.shop` 是 Antigravity 的部署版，无代码改动，本地仓库代码即云端真相
- 用 curl 直接打远程 API 完整复现 + 4 步时间序列测试，比改前端代码加 log 快

## 修复实施（已完成）

用户确认修复后，实施了以下改动（已通过 mock 单元测试验证）：

### 1. Web UI 状态标签细分（`web/static/index.html:404-405`）
跟 Qt UI 对齐，把 catch-all 的"已耗尽"拆成 7 种独立标签：
- active → 活跃（绿 bg-secondary-container）
- disabled → 已禁用（灰 bg-surface-container）
- exhausted → 已耗尽（红 bg-error-container）
- cooldown → 冷却中（灰）
- rate_limited → 限流中（灰）
- abnormal → 异常（红）
- permanent_disabled → 永久禁用（灰）

### 2. toggle 接口加状态白名单（`web/api/proxy.py:128-151`）
- 只允许 `active <-> disabled` 切换
- 对 `abnormal/exhausted/permanent_disabled/rate_limited/cooldown` 返回 400，detail 提示用 activate 接口
- 返回值新增 `status` 字段，方便前端同步状态

### 3. 新增 `/proxy/keys/{id}/activate` 接口（`web/api/proxy.py:154-177`）
- 强制把 status 改成 active，不拒绝任何状态
- 返回 `previous_status` 和 `warning`（abnormal/exhausted 会提示"恢复后可能立即被系统再次禁用"）
- 已 active 时返回友好提示，不报错

### 4. 前端 toggleProxyKey 智能路由（`web/static/index.html:1598`）
- 检测 status 是系统禁用状态时，自动调 activate 而非 toggle
- toggle 被 400 拒绝时自动 fallback 到 activate
- 显示 warning（如有），1 秒后刷新 proxy status 检测反向覆盖

### 测试
- 新建 `tests/test_toggle_activate.py`，mock 数据库验证 5 组场景：
  - toggle 5 种系统禁用状态都正确返回 400 ✓
  - toggle active <-> disabled 正常切换 ✓
  - activate 5 种系统禁用状态都成功恢复 active，abnormal/exhausted 带 warning ✓
  - activate 已 active 的 key 返回友好提示 ✓
  - toggle/activate 不存在的 key 返回 404 ✓
